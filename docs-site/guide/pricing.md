# 定价与计费

## 计价单位

价格统一按**每 1M token** 显示。实际扣费按请求的真实 token 数折算。

## 三种计费类型

| 类型 | 适用 | `model` 之外的差异 |
| --- | --- | --- |
| 按量计费 | 绝大多数对话 / 补全模型 | 按输入、输出、缓存读写分别计价 |
| 按次计费 | 图片生成等按张计价的模型 | 每次调用固定价格 |
| 任务计费 | 视频、批量任务等异步接口 | 按任务时长或任务次数计价 |

## 档位（Tier）

同一个模型可能有多档价格，常见维度：

- **输入 / 输出**：分开计价，输出通常更贵
- **缓存读取**：命中提示词缓存时按更低单价计费
- **缓存写入**：写缓存的单价，分 5 分钟与 1 小时两档
- **长上下文**：超过某个阈值后整体切到更高的档位

模型广场的「分档价格表」会列出每个档位的单价；「按分组定价」会把当前分组的倍率套用上去。

## 最终价格怎么算

```text
费用 = 输入 token / 1M × 输入单价
     + 输出 token / 1M × 输出单价
     + 缓存读 token / 1M × 缓存读单价
     + 缓存写 token / 1M × 缓存写单价
```

其中所有单价都已包含分组倍率。页面默认显示的是**折后价**，切换到别的分组会实时重算。

分组倍率的高低主要反映线路成本与稳定性：**满血为官方直连，单价最高但最稳**；稳定 / 特惠 / 越狱更便宜，高峰期波动也相对明显。

## 余额与扣费

- 预扣：请求开始前按估算上限预扣额度，结束后按实际用量结算并退回差额。
- 余额不足时返回 `402`，不会发起上游请求。
- 用量明细在控制台「日志」页面按请求逐条可查（含 token 数与扣费金额）
- 扣费可能包含**缓存写入**（`cache_creation`）；线路切换或资源调整后缓存失效，会重新产生这笔费用，见[缓存与计费](/faq/cache)。

## 价格变更

上游价格调整后，模型广场的价格会同步更新。已发生的调用按当时的价格结算，不做追溯。
