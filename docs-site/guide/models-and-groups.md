# 模型与分组

## 模型清单

模型是否可用取决于**令牌**的配置：模型白名单、分组、以及该分组是否已开通对应渠道。所以清单以接口返回为准：

```bash
curl "$BASE_URL/v1/models" -H "Authorization: Bearer $NEW_API_KEY"
```

也可以在 <a href="/pricing" target="_blank">模型广场</a> 页面浏览：每个模型会显示供应商、能力（推理 / 工具 / 文件 / 多模态）、上下文长度、支持的协议、所属分组与实时价格。

## 分组

分组决定三件事：**能不能用、多少钱、走哪条线路**。

### 线路来源

| 分组 | 线路来源 | 特点 |
| --- | --- | --- |
| 满血 | **厂商官方 API** | 参数与能力跟官方一致，最稳，价格最高 |
| 稳定 | 上游**订阅账号池** | 价格居中，日常使用够稳，高峰期可能有排队 |
| 特惠 | 上游**订阅账号池** | 价格最低，并发与稳定性最弱，适合非关键任务 |
| 越狱 | 上游**订阅账号池** | 宽松内容策略，同样受账号池波动影响 |

简单记：**只有「满血」是官方直连，其余三个都来自同一类账号池**，差别在调度策略与价格。

### 账号池线路和官方线路的差别

- **并发与限流**由上游账号的配额决定，高峰期更容易遇到 `429` 或偶发 `5xx`
- **能力可能略有缺失**：某些官方专属参数、批处理、文件接口在账号池线路上不一定可用
- **可用性会变**：上游账号可能被调整或下线，模型是否在线以模型广场的实时状态为准
- **数据处理路径不同**：账号池线路的请求由上游第三方账号承载，敏感数据建议只走「满血」
- **提示词缓存不跨账号**：缓存命中绑定到具体上游账号。账号被封禁或调度轮换后，旧缓存全部失效，下一次请求要重新按「缓存写入」计费，表现为**费用突然变高、首 token 变慢**，长系统提示场景最明显（详见[缓存与计费](/faq/cache)）

::: warning 生产环境怎么选
面向用户的线上业务、涉及合规与敏感数据、需要稳定 SLA 的，用**满血**；内部工具与开发调试可以用**稳定**；**特惠 / 越狱不建议承载生产流量**。
:::

### 按场景选分组

| 场景 | 建议分组 | 理由 |
| --- | --- | --- |
| 线上产品、客户可见 | 满血 | 官方线路，能力与稳定性有保证 |
| 内部工具、日常开发 | 稳定 | 价格与稳定性折中 |
| 批量离线任务、可重试 | 特惠 | 成本最低，失败可重跑 |
| 特殊内容策略需求 | 越狱 | 仅用于明确需要时，风险自担 |

## 分组的三个影响

1. **能不能用**：令牌不在某个分组里，就无法用该分组下的模型。
2. **多少钱**：最终价格 = 基准价 × 分组倍率（按 1M token 计）。
3. **多快**：每个分组有独立的 RPM / TPM / RPD，见[速率限制](/guide/rate-limits)。

## 切换分组

分组是绑定在令牌上的，切换方式是**换一个令牌**，或在控制台编辑令牌的分组设置。请求头里不能临时指定分组。
