# 余额与额度

## 报错样例

```json
{ "error": { "message": "insufficient_user_quota", "type": "insufficient_quota" } }
```

对应 HTTP `402`。

## 明明还有余额，为什么失败？

按这个顺序排查：

1. **预扣费**：请求开始前会按估算上限预扣额度。一次超长上下文（例如 800K tokens）的预扣可能大于剩余余额，于是直接被拒。
2. **令牌额度**：令牌自身可以设额度上限，它和账户余额是两回事。
3. **模型价格**：高倍率分组 + 长上下文档位，单次成本可能远超预期。
4. **上游余额**：渠道侧余额耗尽时表现为 5xx，而不是 402。

## 怎么降下来

- 换低倍率分组（例如从满血换到特惠）
- 缩短上下文，或先用便宜模型做初筛
- 给令牌设独立额度，避免单个应用吃光全账户

## 在哪核对

控制台 → 日志，逐条记录模型、token 数与扣费金额；对照模型广场的分档价格表即可复算。
